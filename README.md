# Domain Traffic Inspector

Chromeのサイドパネルで、現在のタブから発生する通信をドメイン別に確認し、通信ルールを管理するManifest V3拡張機能です。計測データとルールは端末内で処理され、開発者のサーバーへ送信されません。

## 主な機能

- ドメイン別のリクエスト数とリソース種別のリアルタイム表示
- 通常モードでの個別ブロック
- 厳格モードでの全ドメイン既定ブロックと許可リスト
- 現在サイトと表示中ドメインから段階的に作れる許可リスト
- 閲覧サイトごとに独立した「サイト保護」と、依存先の5分間一時許可
- 親ドメインの方針を継承し、より具体的なサブドメインで上書きできる階層ルール
- メモ・タグ付きルール管理、検索、一括操作
- ルールのJSONインポート／エクスポート
- ライト／ダークテーマ、キーボードフォーカス、狭いサイドパネルへの対応

> 「全タブ」のルールと厳格モードは全タブ共通です。「このサイト」のルールは、その閲覧サイト内の通信だけに適用されます。通信先は端末内でタブ別に集計し、サイドパネルには選択中のタブだけを表示します。

## 使い方

### 通信先を確認して個別に制御する

1. 対象ページを開き、サイドパネルのドメイン一覧を確認します。
2. `3rd`、広告候補、リソース種別で必要な通信を見分けます。
3. 行の許可／ブロック操作を選び、ページを再読み込みして影響を確認します。

### 必要な通信だけを許可する

1. 「現在サイトを許可」で閲覧先を許可リストの起点にします。
2. 厳格モードへ切り替えます。許可ルールが1件もなければ、サイト表示を含むすべてのドメイン通信を停止します。
3. 一覧から必要な依存先を個別に許可するか、検索・フィルター後に「表示中を許可」を使います。
4. 完成したポリシーへメモとタグを付け、JSONで保存・共有できます。

`example.com` のルールはそのサブドメインにも適用されます。`api.example.com` のような、より具体的なルールを追加すると親ルールより優先されます。厳格モードは全タブへ影響するため、検証用途では専用のChromeプロファイルでの利用を推奨します。

### サイトごとに必要な通信だけを通す

1. 対象サイトでポリシー範囲を「このサイト」へ切り替え、「サイト保護を開始」を選びます。
2. サイト本体は自動で許可され、未登録の外部通信だけがそのサイト内で停止します。
3. 通信一覧から依存先を恒久的に許可するか、時計ボタンで5分だけ許可します。「表示中をサイト許可」で絞り込み結果をまとめて追加できます。
4. 不具合の原因を切り分けたら、一時許可は自動で失効します。全タブのルールは変更されません。

Chrome 145以降ではトップレベルサイトを条件に厳密に範囲指定します。Chrome 114〜144では送信元ドメインを使う互換スコープになるため、サイドパネルに「互換スコープ」と表示します。

このツールの中心は、既製のフィルターリストを適用することではなく、実際に観測した通信から「このサイトには何が必要か」を自分で確認し、その場で最小限のポリシーへ変えることです。Web開発時の依存先監査、プライバシー調査、壊れたサイトの原因切り分けに向いています。

## インストール（開発版）

1. このリポジトリを取得します。
2. Chromeで `chrome://extensions` を開きます。
3. 「デベロッパーモード」を有効にします。
4. 「パッケージ化されていない拡張機能を読み込む」からリポジトリのルートを選びます。
5. ツールバーのアイコンからサイドパネルを開きます。

Chrome 114以降が必要です。

## 権限

- `webRequest` / `<all_urls>`: 全タブの通信先ドメインとリソース種別を端末内でタブ別に集計し、通信ルールを全タブへ適用するため
- `declarativeNetRequest`: ユーザーが指定したドメインをブロックするため
- `alarms`: 5分間の一時許可を、サイドパネルを閉じた後も期限どおり解除するため
- `storage`: ルール、設定、セッション中のタブ別集計を端末内に保存するため
- `sidePanel`: UIをChromeサイドパネルに表示するため

詳細は[プライバシーポリシー](PRIVACY.md)を参照してください。

## 開発

```sh
npm ci
npm run lint
npm test
npm run test:coverage
```

テストはドメイン判定、Chrome APIをモックしたService Worker、JSDOM上のサイドパネル描画・操作を対象にしています。サイト範囲のDNR条件、旧Chrome向け互換スコープ、一時許可の自動失効も含みます。リリース前には[手動スモークテスト](SMOKE_TEST.md)も実施します。

## リリース

`manifest.json`と`package.json`のバージョンを一致させ、`v1.1.0`のようなタグをpushするとGitHub Release用ZIPが生成されます。タグのバージョンとmanifestが一致しない場合は失敗します。

## 判定について

「広告候補」「CDN候補」「サードパーティ」は補助的な推定です。セキュリティ上の安全性を保証するものではありません。ブロック件数ではなく、観測したリクエスト件数を表示します。
